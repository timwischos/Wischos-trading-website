## 客户开发体系 Roadmap

当前业务定位：

- 不做品牌代理，不把 Wischos 包装成大而全平台。
- 分销商和终端客户不冲突，核心是按客户 brief 做定制金属礼品套件供货。
- 目录和套件页面是讨论起点，不是固定限制；客户可以提出非网站产品和不同套件组合。
- 目标市场以欧美审美和采购习惯为标准，优先加拿大、澳洲、欧洲、英国；美国作为标准参考但需考虑关税；中东不是当前主市场。
- MOQ 口径：不要写成 100 sets 绝对门槛。推荐统一表达为 `MOQ is project-dependent. Around 100 sets is a common reference point for custom gift sets, but smaller trial orders can be reviewed case by case depending on product availability, logo method, packaging requirements, and production feasibility.`
- 样品口径：不要公开承诺 free samples / freight collect。推荐表达为项目方向明确后可安排 reference samples 或 custom samples，具体单独沟通。
- 响应时间：qualified briefs within 1–2 business days。
- 定制范围：Logo、包装、颜色、材质、套件组合、private label 都可以讨论，但要基于数量、预算和生产可行性确认。
- 供应链背书：可以写长期合作工厂网络；不要写 lowest price、factory-direct price、we own factories、固定 3 suppliers 等容易误导或削弱议价空间的说法。

## Comparison Table 当前原则

这些表格既服务页面可读性，也服务 SEO/GEO/AI 引用结构。

当前原则：

- 面向客户，而不是内部评审。
- 不使用 `Risk` 这类负面或内部风控字段。
- 使用更自然的列名，例如：
  - `Gift use`
  - `Best fit`

## 以后修改文案的推荐流程

### 修改套件文案

1. 先改文案稿或直接确认最终文案。
2. 把最终内容写入 `src/content/giftSets.ts`。
3. 本地运行构建：

```bash
npm run build
```

4. 提交并推送 GitHub。
5. 检查 Vercel production 部署。

### 修改单品文案

1. 修改 `docs/产品文案相关/单品文案调整/单品文案修改稿-seo+geo.md`。
2. 运行：

```bash
npx tsx src/server/batch-update-product-copy-from-md.ts
```

3. 如只调整 comparison table，再运行：

```bash
npx tsx src/server/update-product-comparison-tables.ts
npx tsx src/server/sync-comparison-tables-to-md.ts
```

4. 抽查 DB 和页面。
5. 扫描客户可见字段，确认没有内部写稿语言。
6. 本地运行构建：

```bash
npm run build
```

7. 提交并推送 GitHub。
8. 检查 Vercel production 部署。
