## 关于前端结构的结论

此前已向用户说明：

- 如果只更新现有数据库字段，例如 `name`、`tagline`、`description`、`highlights`、`materials`、`specifications`、`customizationOptions`、`faqs`、`sourcingNotes`、`seoKeywords`，前端页面结构基本不会变。
- 如果要展示 `metaDescription`、`quickAnswer`、`comparisonTable`、`keyInsight` 这些新字段，就需要改页面结构或把它们折叠进旧字段。
- 用户选择对 WP-101 先试“改变页面结构的完整方式”。

## WP-101 页面结构实验已做的代码改动

### 新增文件

```text
src/content/productSeoGeoOverrides.ts
```

当前作用：

- 定义 SEO/GEO 扩展字段类型：
  - `ProductComparisonTable`
  - `ProductSeoGeoFields`
  - `ProductWithSeoGeo`
- 定义 WP-101 的本地覆盖文案 `wp101Override`。
- 定义 WP-101 本地演示产品 `wp101LocalDemoProduct`。
- 导出 `applyProductSeoGeoOverride(product)`，仅对 `wp-101-brass-crown-bolt-action-pen` 应用覆盖文案，其他产品原样返回。

注意：

- 这是本地覆盖，不写数据库。
- `wp101LocalDemoProduct` 是后来为了解决演示页面依赖数据库卡住的问题新增的。

### 修改文件

```text
src/routes/{-$locale}/products/$productId.tsx
```

当前改动：

- 引入：

```ts
import {
  applyProductSeoGeoOverride,
  wp101LocalDemoProduct,
  type ProductWithSeoGeo,
} from '@/content/productSeoGeoOverrides'
```

- loader 里增加 WP-101 本地直出逻辑：

```ts
if (params.productId === 'wp-101-brass-crown-bolt-action-pen') {
  return { product: wp101LocalDemoProduct, related: [] }
}
```

- 其他产品仍走原来的 `getProductById` 和 `getProducts`。
- WP-101 的 meta description 使用 `product.metaDescription ?? product.tagline`。
- Product JSON-LD 里增加 `additionalProperty`，来源是 `product.specifications`。
- FAQPage JSON-LD 使用新 FAQ。
- `ProductDetailPage` 的 loader data 类型改为 `ProductWithSeoGeo`。

### 修改文件

```text
src/components/sections/ProductDetailSection.tsx
```

当前改动：

- 引入 `ProductWithSeoGeo`。
- 将页面产品类型扩展为支持 SEO/GEO 新字段。
- `relatedProducts` 类型保持兼容数据库产品。
- 在 `About This Product` 区域新增：
